# 修改记录详细编写规范

## 基本信息格式

```markdown
| 字段 | 内容 |
|------|------|
| 修改日期 | 2026-05-18 14:30 |
| 修改类型 | [x] Bug修复 |
| 关联文档 | bug-reports/BUG-2026-05-18-xxx.md |
```

## 修改详情格式

每个修改点必须按以下格式编写：

```markdown
### 修改{N}：{文件名} - {方法名/功能描述}

**位置**：`{相对路径}:{行号范围}`

**修改前**：
```java
// 修改前代码（第 N-M 行）
```

**修改后**：
```java
// 修改后代码
```

**原因**：{说明为何这样修改}
```

### 编写要点

- 一个文件内多个独立改动 → 拆成多个修改点（如"Controller 方法 A"和"Controller 方法 B"是不同点）
- 代码对齐：前后代码保持相同缩进，每段长度不超过 50 行
- 行号精确到范围，如 `第 2460-2476 行`
- 原因说明要简短，2-3 句即可

## 回滚方案格式

> 回滚不使用 git 命令，必须按修改点逐一手动还原。

```markdown
| 序号 | 文件名 | 操作 | 回滚方法 |
|------|--------|------|----------|
| 1 | XxxController.java | 修改 | 见#回滚：XxxController.java |
| 2 | XxxService.java | 新增 | 删除该文件 |
```

每个修改点的回滚格式：

```markdown
### 回滚：{文件名}

**当前代码（修改后）**：
```java
// 第 N 行，修改后的内容
```

**应还原为（修改前）**：
```java
// 原始内容
```

**操作**：找到文件，定位到第 N 行，将内容替换为"修改前"代码。
```

### 注意事项

- 新增文件 → "删除该文件" + "检查引用"
- 删除文件 → "恢复该文件"（需要保存原始内容或从 git 找回）
- 配置文件变更 → 特别标注，可能需要重启服务
